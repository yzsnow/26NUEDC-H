# TASK3 现场操作与调参

`main.py` 仍是唯一入口，TASK3 只是它的一个模式。这份文档只讲 TASK3；
HOLD / SAFE_LOST 的参数在 MAIN 页，两套互不影响。

---

## 0. 三分钟上手

1. 上电，进 MAIN 页，**把 ZERO 做准**（下面第 3 节说为什么这是最重要的一步）。
2. 把球放到中心 O 附近，**第一次按 `TASK3`**。屏幕出黄色 `ARMING`，摆杆闭环
   托着球量配平角。
3. 大字变绿色 `START`（日志同时打 `OL 配平完成，等第二次按 TASK3 发车`）。
   **这一段不计时，想等多久都行**。先看串口日志里的 `OL 配平: 估计 ±x.xx°`：
   - **|估计| ≤ 1.0°** → 机械零点合格，继续。
   - **|估计| > 1.5°** → 按 `STOP`，回第 1 步重做 ZERO。别用调参去补，
     补不过来（第 3 节有数据）。
4. 确认球稳、手离开，**第二次按 `TASK3`**。发车，5 秒从这一帧开始计。
5. 跑完看日志末尾两行 `OL move1` / `OL move2`，把它建议的数填进 TASK3 页的
   `OL A1` / `OL A2`。
6. 再跑一趟（**每趟都是按两次 `TASK3`**）。**这就是全部标定**，
   通常第二趟就进 ±1cm。

> 第二次按键的快慢不影响成绩（离线扫了 0~5s 的按键延时，散布是极限环相位混叠，
> 不是趋势）。按 `ZERO` 之后配平滑窗会清空，下一趟的 `ARMING` 会重新量。
> 板载 USER 按键是**退出程序**，不是切视图。

## 1. 日志怎么读

一趟正常的日志长这样（前缀 `OL` 的都是开环走位段）：

```
OL 配平完成，等第二次按 TASK3 发车              <- 第一次按键之后，屏幕出绿色 START
OL 起跑: θ±9.0°  T1 87ms  T2 236ms  播表 2.55s   <- 第二次按键之后，解出来的时间表
OL 配平: 估计 -0.42°  实补 +0.00°               <- 量出来的机械零偏 / 扣掉死区后真加进表里的量
OL 重算: +5 落点 +4.86cm  T2 -> 243ms           <- 到顶点时按实测位置重算第二段
OL 交棒: 位置 -4.87cm  速度 -0.3cm/s            <- 播表结束、闭环接管的那一刻
OL move1: 该走 +5.00 实走 +4.86 cm  ->  ol_a1_cms2 36.0 -> 35.0
OL move2: 该走 -9.86 实走 -9.93 cm  ->  ol_a2_cms2 36.0 -> 36.3
```

注意 `OL 配平` 打在 `OL 起跑` **之后**（配平角是播表第一帧才抄的），别以为漏了。

需要认识的异常行：

| 日志 | 含义 | 该做什么 |
|---|---|---|
| `OL 配平: 估计 -2.8°` | 机械零点偏了近 3° | 重做 ZERO，不要调 TASK3 参数 |
| `OL 配平完成，等第二次按 TASK3 发车` | 正常：配平收敛，停在 READY 等人按第二次 | 屏幕出绿色 `START`，确认球稳后再按一次 `TASK3` |
| `OL 配平: 滑窗只有 7/32 帧，本趟不补配平角` | 只在 `免回正起跑`＝1 时出现：没先按 `HOLD` 就按了 `TASK3`，配平角没量到 | 这趟作废：按 `HOLD` 等两秒，再按 `TASK3` 重跑 |
| `OL 配平未收敛（等了 4.0s），带着当前配平角起跑` | 回正段闭环压不进判据，走了 `arm_max_ms` 兜底（`免回正起跑`＝1 时不会出现） | 摩擦偏大或零偏偏大。仍会进 READY，但配平角不准，建议按 `STOP` 先修 ZERO |
| `OL move1: ... -> 这趟不可信，不给建议（重跑一趟）` | 这趟受了扰动（丢帧冻住摆杆 / 球顶端头 / 识别离群点），实测距离不代表加速度 | 直接重跑，别动参数 |
| `OL move2: ... -> ol_a2_cms2 36.0 -> 72.0 (夹)` | 建议值被 2 倍上限夹住了 | 正常，多标一趟即可（2 倍一趟、4 倍两趟） |
| `OL: 倾角过大` + 退回闭环 | `ol_a` 太大导致最短行程已经超过 5cm | **减小 `OL DEG`**，不要去改斜坡 |
| `+5` / `-5` 误差都是 7.50cm，且连标几趟都不降 | `OL A1/A2` 填得比真值小很多，解出的保持时长过长，球**顶到端头**了。此后取样点是被限位裁过的值，不再是位移测量，标定爬不回来 | **把 `OL A1/A2` 重新填成公式值**（下一节，默认约 36），不要试图继续标。离线里从 12 起标 3 趟走的是 (20,4)→(30,4)，越标越坏 |
| `OL 交棒: 位置 -4.87 速度 -6.2cm/s` | 交棒速度大 | 走位段末端没停稳，`OL A2` 还没标准 |

## 2. 标定的原理（为什么只用抄一个数）

每段走位的倾角波形关于自己的中点**反对称**，所以 `∫a dt = 0`，
**到点速度恒为零，与加速度标得准不准无关**。标错了只会停错地方，不会停不下来。

而"停在哪"有闭式解：`d = A·(T² + T(r+f) + r²/3 + r·f/2 + f²/6)`。
正着用解出保持时长 T（程序每次起跑自动算），反着用就是标定：

```
A_真 = A_设 × |实测距离| / |目标距离|
```

所以标定不是试凑毫秒值，是**跑一趟抄一个数**。两段分开标，因为 move2 更快、
摩擦占总加速度的比例更小，有效 A 天生比 move1 大 1.1~1.5 倍——
日志里看到 `ol_a1 26 / ol_a2 51` 这种一降一升是**正常的**，不是出错。

起步估值：`A ≈ (5/7)·g·sin(OL DEG / 连杆比)`。默认 9 电机度、连杆比 3 → 约 36。

**这个起步值必须自己按公式算一遍，别指望标定能从很远的地方爬回来。**
标定是乘法递推，它的收敛前提是每趟测到的都是"真实位移"；一旦 `OL A` 小到让球
顶上端头，取样点就变成被限位裁过的常数，递推的输入是假的。离线从 A=12 起标
（真值 36），三趟走的是 `(20,4)` → `(30,4)`，`ol_a2` 反而掉到 4。
从 A=36 或 A=100 起标都正常收敛。

## 3. 最重要的一件事：机械零点

反对称只保证"**命令角产生的**那部分加速度积分为零"。机械零点偏了 z 度，
就多出一个全程不变的偏置加速度，它不反对称，一路积成 ½·a_off·T²。
连杆比 2.5、z=2° 时折合 9.8 cm/s²，move1 跑 1.4 秒就多走 9cm——球直接出杆。

程序会自动补一部分：ARM 段闭环托着球停在中心时，`theta_cmd` 就稳定在 −z 附近，
把它当直流偏置加到整张表上（日志第一行就是这个量）。但**补偿只能减轻，不能消除**。
离线 216 工况按零偏分组（误差取球的真值，执行器取真实的半帧滞后模型）：

| 机械零偏 | 纯闭环 最坏 / 最长 | 双段（标定3趟）最坏 / 最长 |
|---|---|---|
| 0° | 1.73cm / 5.18s | **0.97cm / 5.15s** |
| +2° | 1.28cm / 5.45s | 1.09cm / 5.45s |
| −2° | 1.32cm / 5.28s | 3.43cm / 4.65s |

闭环对零偏几乎不敏感（级联本身有积分作用），开环没有这个机制。**结论：**

- 零点做得准（`OL 配平` 估计值在 ±1° 内）→ 开双段，又快又准。
- 零点做不准、又来不及修机械 → `OL ON` 改成 **0** 走纯闭环。牺牲时间换精度。

## 4. 调参顺序

TASK3 页的参数就是按现场顺序排的，从上往下调，**不要跳着调**。

**第一轮 —— 只动这两个**

| 参数 | 什么时候动 |
|---|---|
| `OL A1` / `OL A2` | 每趟按日志建议抄。这是唯一的常规标定动作 |
| `OL DEG` | 走位太慢就加大（同时 A1/A2 要重标）；报"倾角过大"就减小 |

**第二轮 —— 走位段还是不满意**

| 参数 | 症状 → 动作 |
|---|---|
| `OL DWELL` | 评委看不出"在 +5 停过" → 加大（默认 300ms） |
| `OL LEAD` | 交棒位置系统性偏一侧 → 微调（默认 20ms＝半帧） |
| `OL RAMP` / `OL FLIP` | 摆杆动作太猛、机械异响 → 加大。代价是最短行程变长 |

**第三轮 —— 守位段（稳在 −5cm）**

`KP / KV / KA` **不是三个旋钮，是同一个带宽 ωn 的三个投影**。
从 `omega` 到球位置是三重积分，闭环特征方程 `s³ + c·ka·s² + c·kv·s + c·kv·kp = 0`，
按 Butterworth 配极点得 `ka = 2ωn/c`、`kv = 2ωn²/c`、`kp = ωn/2`（c ≈ 4.08）。
**只动 ωn，然后三个一起换：**

| ωn | KP | KV | KA | 说明 |
|---|---|---|---|---|
| 2.5 | 1.25 | 3.1 | 1.2 | 稳，末端修正慢 |
| **3.0** | **1.5** | **4.4** | **1.5** | **默认** |
| 3.5 | 1.75 | 6.0 | 1.7 | 实物噪声很小时可以试 |

两条容易踩的：

- **`KA` 不能调到 0**。没有 s² 项的三次多项式必然不稳定，跟 KV 多大无关。
  KA 是这个环里唯一的相位超前来源。
- **ωn 上限不高**，由量测链滞后决定。离线 ωn=4 开始变差、ωn=5 发散。
  `A LPF` 也别低于 0.4（它的极点会挤到 ωn 附近）。

**第四轮 —— 起跑判据**（一般不用动）

`ARM POS/W/TRIM/MS` 决定什么时候算"配平好了"。ARM / READY 两段**都不计入 5 秒**，
计时从第二次按键那一帧才开始，所以让它多等一会儿是免费的。
`ARM TRIM` 是配平角滑窗峰峰值的门槛；`ARM MAX` 是兜底：等这么久还不收敛就带着
当前值进 READY（宁可不准也不能没反应）。

另外两个开关改的是流程本身，不是判据：

- `ARM CONF`(`二次确认`，默认 1)＝0 → 配平一好就自动发车，不等第二次按键。
  只有在"按一下就跑"比"看一眼配平角再决定"更重要时才关。
- `ARM SKIP`(`免回正起跑`，默认 0)＝1 → 整个配平段都不要，按一次 `TASK3` 立刻发车，
  球完全由人摆正。这一档配平角改在 `HOLD` 段量（先按 `HOLD` 等两秒以上再按 `TASK3`），
  `ARM CONF` 和上面这组判据一起失效。

## 5. 已知限制（都不是 TASK3 能自己解决的）

1. **播表途中丢球会把摆杆冻在半路。** `main.py` 在检测丢失那一帧既不调
   `t3.update()` 也不调 `drive_motor()`，摆杆保持上一个绝对位置。连续丢超过
   `lost_timeout_ms` 会被主程序抢去 SAFE_LOST，这一趟就废了。
   不改主程序的缓解办法：把 MAIN 页的 `lost_timeout_ms` 调大。
   离线"掉帧 8% 连丢 5 帧"那档，纯闭环和双段都各有 2/12 趟因此报废。
2. **摩擦死区决定精度地板。** 摩擦 1.5cm/s²、连杆比 3 时，球在 ±0.37° 摆杆角
   范围内都能静止不动，闭环无法收敛到一个点，只能打极限环。
3. **离群点仍然是双段的软肋。** 离线"掉帧5%连3 + 离群3%"那档双段 −5 最坏 5.42cm，
   纯闭环 1.60cm。取样点已经取 5 帧中位数，但闭环对尖峰的整段反应还是会污染
   配平估计。识别质量差的场地建议 `OL ON = 0`。
4. **程序退出时球停在 −5cm**（`LEVEL_BEAM_ON_EXIT = False`）：退出不回水平，
   电机继续使能锁位。收摊搬运前记得临时改回 `True`，否则球会滚走。

## 6. 离线复现这些数字

`_sim_task3.py` 是临时验证台（不在 `app.yaml` 里，验完可以删）：

```bash
python _sim_task3.py math      # 校验距离闭式解（应是 5.0000 / 10.0000cm，末速 0）
python _sim_task3.py nominal   # 标称 + 实感两档，开环 vs 闭环
python _sim_task3.py drop      # 掉帧 / 离群点敏感度
python _sim_task3.py calib     # 标定收敛性（故意把 ol_a 设错）
python _sim_task3.py sweep     # 216 工况扫描
```

**这些都是模型结论，不是台架结论。** 模型里已经照抄了
`ball_position.AdaptiveAlphaBetaFilter`（包括它 0.3 秒滞后的速度输出）、
`main.py` 丢帧那一帧不发电机命令的行为、以及 `drive_mode=0` 的半帧滞后，
但摩擦、连杆比、相机延迟都是估的。**台架数据优先于这里任何一个数字。**
