# 摆杆滚球控制程序（H题 摆杆部分，MaixCAM2）

识别（YOLO26检测钢球）+ 控制（UART直控 ZDT Y42 Emm固件闭环步进）一体的独立工程。
入口 `main.py`，MaixVision 打开本文件夹直接运行。

本工程不实现赛题第 1 问的图传、录像或回放。比赛图传由车载外部 DJI Action 5 Pro 独立完成，
使用自身供电和接收/存储设备，不与本工程的 MaixCAM2、MSPM0、传感器或电机控制线连接。
这里的相机画面只用于钢球识别、摆杆闭环和本地调试；MaixVision 的帧回传也不属于比赛图传链路。

## 一个入口，两套参数

只有 `main.py` 一个入口。但 **TASK3 的控制器和参数是独立的一套**，
和 HOLD 完全不共享增益：

| 模式 | 控制器 | 参数 | 存档 |
|---|---|---|---|
| HOLD / SAFE_LOST | `cascade.py` | `main.py` 的 `CONFIG` | `/root/ctrl_config.json` |
| **TASK3** | **`task3_ctrl.py`** | **`task3_config.py`** | **`/root/task3_config.json`** |

调 HOLD 动不到 TASK3，反过来也一样。调参页用 `PAGE` 键在 `MAIN` / `TASK3`
两页之间切换，`SAVE` 一次把两个文件都写掉。

两套闭环现在使用同一种控制律：快速位置差分测速、按剩余距离制动限速、远近增益
线性混合。独立的是控制器状态和参数，而不是核心公式；TASK3 的开环走位与任务状态机
仍然只属于 TASK3。

唯一的例外是**方向反转 / 行程限幅 / 软限位起点**：这三个是机器的事实，不是可调
参数，两份拷贝必然有一份过期，所以只在 MAIN 页改，由主程序单向镜像给 TASK3
（见 `task3_config.MIRRORED_FROM_MAIN`）。

详见下面的 [TASK3](#task3) 一节。

## 控制结构：三级级联（已按"西风h题"方案重写）

原来是**一个位置PID直接输出电机角度**。问题在于：从电机角度到钢球位置中间还夹着
"倾角→重力分量→加速度→速度→位置"这一串积分，单环PID必须用同一个输出同时干两件事
——既要顶住机械零点偏差撑出一个静态倾角，又要给钢球提供阻尼，两者互相打架。
表现就是球停在中心旁边几毫米不动、到点后来回过冲。

现在改成**三级级联，电机命令的是倾角速度而不是倾角**：

```text
目标位置 x_ref ──▶ ① 位置外环 + 制动限速 ──▶ v_ref (cm/s)  目标钢球速度
                 v_ref ──▶ ② 钢球速度环 + 加速度阻尼 ──▶ omega (电机°/s)
                 omega ──▶ ③ 行程限幅器 ──▶ 积分 ──▶ theta_cmd (电机°) ──▶ 电机
```

带宽从内到外递减：电机 > 钢球速度 > 钢球位置。关键收益：

- **静态倾角由 `theta = ∫omega` 自己生成**，机械零点偏差被结构本身消掉，
  所以位置积分 `KI X` 默认 0 也能停在正中心（离线验证：人为加 2°机械零偏，
  最终误差 0.000 cm，程序自己找到 −2.00°的配平）；
- **加速度阻尼 `KA` 是超前项**，在球到达目标*之前*就开始回倾，而不是冲过去再拉回来；
- **控制用球速从滤波后的位置快速差分得到**，只做短低通，避免 alpha-beta 速度状态
  约 0.3 s 的滞后；
- **制动限速按剩余距离收紧目标球速**，远处可以快，接近中心时提前刹车；
- **行程保护独立于控制环**：软限位从 `行程限幅 × 软限位起点` 开始按剩余行程线性缩放
  向外的角速度，卡球压力测试下角度停在限幅值不再外移。

代码位置：`cascade.py`（纯算法，不含任何硬件调用，可在PC上单独跑）。
`pid.py` 是旧的单环实现，**已不再被引用**，保留仅作对照，可以删除。

### 两种电机驱动方式（`驱动模式`）

| 值 | 方式 | 说明 |
|---|---|---|
| **0（默认）** | 绝对位置 0xFD | 把 omega 积分成角度再发绝对位置，分辨率一个细分步 0.1125°。发送速度按 \|omega\| 实时匹配，让电机"刚好在下一帧到位"，因此动作连续；主机停止通信电机自动停在原地，天生安全 |
| 1 | 速度模式 0xF6 | 真正的连续转动，但协议里速度字段是**整数RPM**，即一档 6 电机°/s。实测 3 cm 误差时只有 0/6/12°/s 三档可用，接近目标时量化严重；且失联后电机会一直转，必须每帧喂命令 |

先用默认的 0。只有在实物上觉得位置模式仍不够顺滑时才试 1。

## 接线

| MaixCAM2 | 电机 |
|---|---|
| B0 (UART2_TX) | RX |
| B1 (UART2_RX) | TX |
| GND | GND |

TX↔RX **交叉接**，GND 必须接且要粗短（少了它电机一转就丢帧报 `MOTOR EE`）。
电机：地址1、波特率115200、校验固定0x6B、细分16（出厂默认，改了细分要同步改
`zdt_motor.py` 的 `PULSES_PER_REV`）。**开机前把摆杆摆到水平**，程序启动会把当前
位置清零作为水平基准（0°）。

### 底盘惯性前馈串口

底盘 `PA8/UART1_TX` 通过第二路串口给 MaixCAM2 单向发送 32 字节、50 Hz 惯性
遥测，固定接 MaixCAM2 `PA31/UART1_RX`（MaixPy pinmap 名称为 `A31`）。运行
`uart_pin_probe.py` 可只读确认当前固件是否支持该复用。底盘与 MaixCAM2 必须共地，
且只能接 MCU TTL 电平。

前馈只叠加在 `HOLD`，不改变 TASK3。默认 `FF ON=0`；CRC、序号、状态、bit2 和
100 ms 新帧超时全部门控，失败时视觉闭环继续运行，附加倾角在默认 350 ms 内撤销。
详细接线、调参顺序、CSV 字段和回退方式见 [惯性前馈_现场操作.md](惯性前馈_现场操作.md)。

### 供电

MaixCAM2 用内置电池时，电机堵转会把电池拉到欠压保护，表现是**日志无 traceback
直接断掉然后重启**（软件异常一定有堆栈，没堆栈就是硬件级瞬断）。所以：

- 电机 24V 与 MaixCAM2 供电分开，只共信号地；
- `行程限幅` 必须按实物连杆标定（默认 30 电机度是 `probe.py` 量出来的机械边界，
  换机器一定要重量），限幅小于机械边界才不会顶着硬限位堵转；
- 电池供电又不稳时可以把 `加减速档` 从 0 调到 10 上下，用加减速斜坡削掉启动
  电流峰值，代价是响应慢一点；
- 卡球超过 `卡球判定` 时程序会**主动停机并回 IDLE**，不再顶着限位堵转。

## 方向约定（只有一个地方管符号）

正的位置误差（球在目标左边）必须产生**正的电机角度**，`方向反转` = 0。
这与实物上验证过的单环 PID 版本（`yz--h-ctrl`）一致，符号由
`CascadeController.update` / `Task3Controller.update` 各自只翻转一次——注意它与参考文档的
`omega = -Kv*err` 相反，
因为文档定义的摆杆正方向和这台机器的电机极性不同。**不要在别处再加负号。**

方向反了的后果不只是"控制不对"：摆杆会朝错误方向越推越偏，一路顶到限幅堵转，
于是触发上面那条掉电重启。所以方向没确认对之前不要放球跑闭环。

## 屏幕操作

- 运行视图底栏：`HOLD`(球保持中心O) / `TASK3`(＋5→−5任务) / `STOP`(急停) /
  `ZERO`(当前姿态设为水平) / `LIGHT`(板载补光灯开关) / `TUNE`(进调参页)。
- **板载 USER 按键 = 退出整个程序**（切视图用底栏的 `TUNE` / `BACK`）。它走的是
  正常退出流程，所以跑过 TASK3 之后按它，摆杆仍然保持倾角把球锁在 −5cm
  （见「退出时球停在 −5cm」）。程序自己接管了这颗按键（`rm_default_listener`），
  否则系统默认处理会直接杀进程，退出流程根本不执行，摆杆一松球就滚了。
- **中心轴线是亮黄色**，中心 O 是白十字，当前目标是红十字。
- **任务秒数是屏幕上最大的一个数**，青色。它从起跑那一帧就开始实时走字，
  DONE 之后定格在总耗时上；超过 5s 变红。两端实测误差 `+5:0.12 −5:0.28`
  用白字排在它右边。
- 发车之前同一个位置、同样大小显示**下一步该做什么**：黄色 `ARMING`＝正在配平、
  等它；绿色 `START`＝配平好了，**再按一次 `TASK3`** 才发车。绿色＝该你动手。
- **`LIGHT`** 切换 MaixCAM2 板载的照明 LED（B25 引脚，MaixCAM-Pro 是 B3）。
  亮着时按钮底色变琥珀色，所以不用占状态栏一行也知道当前状态。默认关，
  退出程序时自动关——它和电机共用同一块电池，而电池被拉垮正是板子无故重启的
  原因。板子上没有这颗灯、或引脚被别的功能占用时，启动日志会打印
  `board light unavailable: ...`，按钮按下去不报错也不生效。
  开灯会改变画面亮度，**训练集是在什么光照下采的，就尽量在什么光照下跑**，
  临时开灯救场之前先确认识别率没有反而变差。
- 顶栏左边是位置/目标/误差，右边是模式和帧率；第二行右侧新增 **`V*` 目标钢球速度**
  和 **`W` 命令角速度**——调中间那一级必须看这两个数，否则分不清是位置环要得太猛
  还是速度环跟不上。
- 黄字 `TRAVEL LIMIT` 是**实时状态**（大动作时闪一下正常）；红字才是锁存故障。
- **TASK3 结束后锁死在 −5cm**：显示 `x.xxs +5:0.12 −5:0.28`（耗时 + 两端实测误差），
  此后目标永远是 −5cm。解除只能按 `HOLD` / `TASK3` / `STOP`。超时同样锁在 −5cm，
  不回中心，只把 `TASK3 OVERTIME` 标红。
- 调参页：`< >`选参数，`- +`修改，`STEP`切步进倍率(×1/×5/×10)，
  **`PAGE` 在 `MAIN` / `TASK3` 两页之间切换**（顶栏左上角显示当前是哪一页，
  两页各自记住光标位置），`SAVE` 把两页分别存到 `/root/ctrl_config.json` 和
  `/root/task3_config.json`（下次启动自动加载），`BACK`返回。调参时控制环不中断。
  参数名除 `KP`/`KI`/`KV`/`KA` 这些增益符号外都是中文，数值用黑字白底显示
  （画在实时画面上，没有底衬的话背景一深一浅都看不清）。系统里找不到中文字体时
  会自动退回英文标签——启动日志会打印用的是哪个字体。

## 现场调试顺序（必须从内环往外环，不要三级同时改）

> 增益单位是**电机度**，不是摆杆度。`KV`/`KA`/`最大角速度` 跟的是**连杆比**
> （默认假设约 3 电机°/摆杆°），**不是**跟 `行程限幅`。连杆比不同才需要缩放它们；
> 单独收紧 `行程限幅` 不要动增益——离线试过把 `KV` 跟着缩小，过冲从 0.2 cm 涨到
> 2.7 cm 还慢了 0.7 s。
>
> `行程限幅` / `软限位起点` / `方向反转` 只在 `MAIN` 页改，TASK3 那一套是主程序
> 单向镜像过去的（见开头「一个入口，两套参数」）。这三个是机器的事实不是增益，
> 两份拷贝必然有一份过期，而过期的 `方向反转` 会把摆杆一路推到限位堵转。
>
> **改过增益的存档会失效**：`ctrl_config.json` / `task3_config.json` 各自带版本号，
> 默认值量级变动后旧存档会被整个丢弃（启动日志会打印 `ignoring stale config`），
> 避免旧的激进参数被悄悄恢复。要沿用旧值就重新调一遍再 `SAVE`。

1. **零点与方向**（先不放球，脱开连杆看电机不报警）：摆平→`ZERO`。
   放球在中心右侧，按 `HOLD`——摆杆必须朝"把球送回中心"的方向倾。
   反了**只改 `方向反转`** 一处，不要在别的地方另加负号。
2. **行程限幅**：`行程限幅` 从小往大试，找到连杆两侧机械边界后设为边界的 80%；
   `软限位起点` 保持 0.75（即最后 25% 行程内开始减速）。这一步必须先做，
   否则后面调增益时会直接撞机械限位。
3. **钢球速度环**（中间级，最关键）：保持 `球速来源`=1、`球速滤波`=0.7，先把
   `KP 远/近` 一起压小到 0.5，让 `V*` 变化平缓，这样看到的基本就是速度环自己的表现。
   - `KV 远/近` 同步由小到大加，看球的速度跟随和 `W` 是否抖；球速来回振荡就别再加；
   - `KA 远/近` 同步调整来抑制过冲；`W` 高频抖动就适当减小 `加速度滤波`，但先别低于 0.4；
   - 正常工况下 `M`（命令角度）应明显小于 `行程限幅`，经常顶到限幅说明太激进。
4. **位置外环**：HOLD 的目标恒为中心 O，所以测试方法是**把球放到偏离处松手**，
   看它回中心。`KP 远/近` 从 0.5 同步往上加，先用 +2cm 起手，再放到 +5、−5 复测。
   **远距离太慢先加 `最大球速`；回中仍过冲先减 `制动减速度`；末端补不动再加
   `最低限速`。**默认远近值相同，整套稳定后才有必要分开调。
   只有确实存在稳态静差时才加一点 `KI X`（默认 0，因为级联本身就有积分作用）。
5. **TASK3**：以上 1~4 调的是 `MAIN` 页（HOLD 用）。TASK3 是另一套增益，
   按 `PAGE` 切到 `TASK3` 页单独调，见下面 [TASK3](#task3) 一节的调参顺序。
   `MAIN` 调好只说明机械和方向没问题，不代表 TASK3 能过。
6. 最后加小车行驶扰动测试。

HOLD 默认闭环带宽已与 TASK3 守位段对齐。仿真只能验证公式和趋势，最终仍以实物的
回中时间、过冲、`W` 抖动和最大倾角为准；TASK3 的验收数据见 [TASK3](#task3) 一节末尾。

## 帧率

顶栏那个 `FPS` 是 `min(相机帧率, 循环帧率)`，它说明不了该修哪里。**先量再改**：

```bash
CTRL_PROF=1 python main.py
```

每秒打一行分项耗时，四栏加起来就是一帧的预算：

```
PROF 21fps  相机12.3 检测28.1 控制1.4 画面5.8 ms/帧  (画面分频 1)
```

- **相机** = `cam.read()` 等下一帧。这一栏大 = 被传感器帧率卡住，改代码没用。
- **检测** = 裁剪 + NPU 推理。通常是大头。
- **控制** = 滤波、控制律、串口发送（串口是非阻塞的，这栏本来就该接近 0；
  它要是大了，先看是不是开了 `CTRL_TELEM=1`，每帧一行 CSV 不便宜）。
- **画面** = 叠图 + `disp.show()`。

按性价比排的手段：

1. **帧率测试不要连接 MaixVision 调试预览。** IDE 连接时每帧可能被 JPEG 编码回传，
   这经常是最大的一笔，而且完全不体现在上面任何一栏里（它藏在 `disp.show` 和系统开销里）。
   这是开发调试开销，不是赛题图传功能；从设备菜单独立启动 app 再看一次 FPS。
2. **降低画面刷新频率。** MAIN 页 `画面分频`(`DRAW EVRY`) 改成 2 或 3：叠图和
   `disp.show()` 每 N 帧才做一次。**这一档不花任何延迟代价**——电机命令在绘制
   之前就发出去了，跳过的绘制只是不再拖慢下一帧的采集。触摸仍然每帧都读，
   只有按钮高亮会晚一帧。先看 `画面` 那一栏值不值得，NPU 占主导的机器上这招没用。
3. **让裁剪尺寸正好等于模型输入。** 启动日志现在会打
   `detect: 模型输入 480x160，裁剪 480x170 -> 每帧多一次内部缩放`。
   对不上就每帧白白重采样一次，而且球也被重采样了（略微掉精度）。
   改 `main.py` 的 `DETECTION_ROI_HEIGHT` 对齐即可，代价是纵向少看几行像素，
   改之前确认球不会跑出这条带。
4. **`LOW_LATENCY_MODE = False`（有陷阱，别无脑开）。** 它会打开 YOLO 的
   `dual_buff`，NPU 流水线起来，FPS 明显上去——但你拿到的检测结果**老了一帧**。
   净延迟大致从「一次推理时间」变成「两个新帧时间」，可能反而更差。
   而且 §4.3 已经讲过，这个闭环的带宽上限就是量测链滞后定的，
   **用延迟换来的帧率会被带宽吃回去**。
   一个有用的区分：TASK3 的走位段是纯开环播表、根本不看球，多一帧延迟不花钱；
   只有守位段的闭环会疼。所以要开就先只在纯闭环模式下对比一次落点。

数字变好之前不要动增益：HOLD 与 TASK3 的 `KV`/`KA` 都是按 25fps 左右的滞后配的极点，
帧率一变，`task3_config.py` §4.3 那张 ωn 表就要跟着重算。

## 故障速查

| 现象 | 处理 |
|---|---|
| 顶栏 MOTOR E2 x3 | 电机保护/未使能：检查供电、是否堵转；程序已自动补使能 |
| MOTOR EE x5 | 帧格式错。**首先确认 `位置回读` = 0**——本机固件不认 0x36 读位置命令，每问一次回一个 EE，这是最常见的原因，所以默认关闭。排除它之后再查接线干扰、波特率、校验方式。单次 EE 不报警（阈值 5 次），避免偶发干扰锁死报警行 |
| BALL LOST 常驻 | 降 `置信度`、检查光照/模型（可按 `LIGHT` 开板载补光灯试试，但注意它会改变画面亮度）；丢球超500ms摆杆按 `丢球回位速度` 匀速回水平（不是瞬间归零，避免把球甩出去） |
| 按 LIGHT 没反应 | 看启动日志有没有 `board light unavailable`：板子没有这颗灯（初代 MaixCAM），或 B25/B3 被别的复用功能占了 |
| BALL STUCK -> STOP | 顶到限幅且球不动，程序已主动停机回 IDLE（堵转是掉电重启的直接原因）。检查连杆是否卡死、`行程限幅` 是否太小、`方向反转` 是否反 |
| 黄字 TRAVEL LIMIT 常亮 | 外环过激：减 `KP 远/近` / `最大球速`，或 `行程限幅` 标定过小 |
| 球来回振荡 | `KV 远/近` 太大或 `KA 远/近` 太小；也可能帧率低（先按「[帧率](#帧率)」一节量一遍，别凭感觉调增益） |
| 帧率偏低 | 见「[帧率](#帧率)」：`CTRL_PROF=1` 打分项耗时，先从设备菜单独立运行、不要连接 MaixVision 调试预览 |
| 停在中心旁不动 | 级联理论上不该出现；先确认 `方向反转` 和 `行程限幅`，再看 `W` 是否被限幅压成 0 |
| 摆杆动作一顿一顿 | `最小转速` 太大（拉低到 5 左右）或 `加减速档` 太大；也可试 `驱动模式`=1 |
| 摆杆越推越偏 | 极性反了：翻 `方向反转`。注意这会一路顶到限幅堵转 → 可能掉电重启 |
| 日志无堆栈直接断然后重启 | 不是程序崩溃，是硬件掉电。见上面「供电」一节 |

## TASK3

> 题目：小车静止，球从中心 O 走到 +5cm，折返走到 −5cm 并稳定在该点附近；
> **总时间 ≤5s，±5cm 处最大误差绝对值 ≤1cm**。

### 两个文件

| 文件 | 内容 |
|---|---|
| `task3_config.py` | **唯一改参数的地方**：任务定义、退出行为、增益表、TASK3 调参页 |
| `task3_ctrl.py` | 控制律 + 状态机，纯算法无硬件调用，可在 PC 上单独跑仿真 |

相机、电机、屏幕、主循环仍然是 `main.py` 的，按 `TASK3` 键切进去即可。

### HOLD 与 TASK3 守位共用的闭环优化

HOLD 已经采用下面的制动限速和远近增益，并且同样默认用滤波后位置的一阶差分测速。
TASK3 真正额外增加的是 `0 -> +5 -> -5` 开环播表、ARM/READY 配平和稳定判定状态机。

**制动限速**（位置外环里）：

```text
v_cap = min(最大球速, max(最低限速, sqrt(2 × 制动减速度 × |误差|)))
```

没有这一项，快和准只能二选一：`KP` 大就冲过头，`KP` 小就响应慢。
有了它，`KP` 可以调大来抢起步时间，同时接近目标时的速度永远不超过
"以 `制动减速度` 减速刚好能停住"的值。过冲就减小 `制动减速度`，到点太慢就加大。

**远近双档增益**：`KP/KV/KA` 各有 `远`/`近` 两个值，按 `|误差|` 在 `远近分界` 区间内
线性混合——远处要冲，近处要稳。按阈值硬切换会让球停在分界线附近时高频抖动，
所以是线性混合。把 `*_near` 设成和 `*_far` 一样即可关掉这个特性。

**远近双档现在取同一个值**（`KV 远`=`KV 近`=4.4）。早先的版本刻意把 `KV 近` 调到 11、
远大于 `KV 远` 的 6，理由是"近端要在很短距离内把球速拉到 0"。这个理由**是错的**：
带宽上限由量测链的滞后决定，而滞后远近一样大，近端根本吃不下更高的增益。
把仿真里的球速换成忠实照抄 `ball_position.AdaptiveAlphaBetaFilter` 的版本
（它的速度是位置残差积出来的，β 只有 0.01~0.12，滞后约 0.3 秒）之后，那组增益
**是发散的**。远近机制本身保留着，想分档随时能改，只是默认不用。

`KP / KV / KA` 也不是三个独立旋钮。电机命令的是倾角**速度**，所以 `omega` 到球位置
是三重积分，闭环特征方程 `s³ + c·ka·s² + c·kv·s + c·kv·kp = 0`（c ≈ 4.08 cm/s² 每电机度）——
三个增益填的是同一个三次多项式的三个系数，是**一个带宽 ωn 的三个投影**。
按 Butterworth 配极点得 `ka = 2ωn/c`、`kv = 2ωn²/c`、`kp = ωn/2`；默认 ωn = 3.0。
要快要慢只动 ωn 然后三个一起重算，推导和 ωn 对照表见 `task3_config.py` 第 4.3 节。

由此得到两条跟直觉相反的结论：**`KA` 不能调到 0**（没有 s² 项的三次多项式必然
不稳定，跟 KV 多大无关，KA 是这个环里唯一的相位超前来源）；**ωn 上限不高**
（离线 ωn=4 开始变差、ωn=5 发散，而旧默认值反解出来正好是 ωn ≈ 5）。

第 31~36 行（`二次确认` / `起跑*` / `配平*`）描述的是回正配平段，
**`免回正起跑`＝1 时它们一个都不参与**（那一档没有配平段，也就没有"等它配平完"
这回事，`二次确认` 一起失效）。

**`STEP` 键先看一眼**：上表的步进是 ×1 档。`开环加速1/2` 一步只有 0.5，
在 36 上面按一下只动 1.4%（落点变 0.07cm）——要从 36 调到 9 得按 54 下。
标定 `OL A1/A2` 之前先按 `STEP` 切到 **×10**（一步 5.0），否则会误判成"调了没反应"。

调参顺序（`开环走位`＝1 时）：

1. **先标走位段，这一步占全部工作量的九成。**
   跑一趟，把日志 `OL move1` / `OL move2` 建议的数填进 `开环加速1`(`OL A1`) /
   `开环加速2`(`OL A2`)。公式是 `新 A = 当前 A × 实走 ÷ 该走`，日志没给建议
   （落点差到 30% 以外时程序会自己拦掉）就手算。
   `KV`/`KA`/`KP` 这时**一个都别碰**——去程是开环播表，闭环增益碰不到它。
2. **总时间超 5s** 才动 `开环倾角`(`OL DEG`)，加大即可。
   改完 `开环加速1/2` 全部作废（A ∝ sinθ），按 `A_新 ≈ A_旧 × θ_新 ÷ θ_旧`
   重填再标一趟。改 `开环斜坡`/`开环反向` **不会**让标定作废（闭式解里 r、f 是
   显式项），但会改变解出的保持时长。
3. **摆杆动作太猛、机械异响**：加大 `开环斜坡`(`OL RAMP`) / `开环反向`(`OL FLIP`)。
   代价是最短行程变长，加过头会报 `OL: 倾角过大` 并退回闭环。
4. **守位段（稳在 −5cm）**：`KP 远/近`、`KV 远/近`、`KA 远/近` 是**同一个带宽 ωn
   的三个投影**，只动 ωn 然后六个格子一起换（对照表见上一节）。单独动一个只会让
   极点乱跑。过冲减 `制动减速度`(`A BRAKE`)；末端最后一点补不动加
   `最低限速`(`V FLOOR`)；`W` 高频抖减 `加速度滤波`(`A LPF`)，但别低于 0.4。
5. **折返判不出来**（球在 +5 附近来回但不走 −5）：放宽 `折返速度`(`ARRIVE V`)，
   或减小 `折返确认`(`ARRIVE MS`)。反过来球高速穿过 +5 就折返（`+5:` 那个数很大），
   收紧 `折返速度`。
6. **迟迟不 DONE**：放宽 `稳定位置`(`SETTLE P`) / `稳定速度`(`SETTLE V`)，但放宽到
   1cm 以上就等于自欺欺人——屏幕上的 `−5:` 是独立量的真实误差，不受这两个窗口影响。

`开环走位`＝0（纯闭环）时跳过 1~3，直接从第 4 步开始，此时 `KP/KV/KA` 才管去程。

`SAVE` 不分页，一次把两页分别写进各自的文件（`/root/ctrl_config.json` 和
`/root/task3_config.json`），免得还要记住刚才停在哪一页——但两个文件的内容
始终是分开的，存 TASK3 不会污染 HOLD 的增益。

### 退出时球停在 −5cm

`task3_config.LEVEL_BEAM_ON_EXIT = False`：**跑过 TASK3 之后**退出时不把摆杆
回水平，保持最后一次命令的倾角、电机继续使能锁位，球留在 −5cm。
回水平会撤掉正在托住球的那点配平倾角，球就滚走了。
只有收摊搬运时才临时改成 `True`。没进过 TASK3 的退出仍然照旧回水平。

同样地，`Task3FSM` 没有 FAIL 态：超时只把屏幕标红，目标永远是 −5cm，绝不松开摆杆。
DONE 之后即使丢球也不会转 SAFE_LOST——静止的球正是检测最容易丢的情况，
按丢球处理会把刚跑完的成绩毁掉。

### 屏幕操作

**按两次 `TASK3` 才发车**（默认档：`免回正起跑`＝0、`二次确认`＝1）：

1. 把球放到中心 O 附近，**第一次按 `TASK3`**。摆杆闭环把球托在中心量配平角，
   屏幕大字显示黄色 `ARMING`。
2. 配平收敛后大字变绿色 `START`，同时日志打 `OL 配平完成，等第二次按 TASK3 发车`。
   这时想等多久都行——**READY 段不计入 5 秒**（`t0` 要到发车那一帧才置）。
3. 确认球稳、手离开，**第二次按 `TASK3`** 发车。计时和播表从这一帧同时起算，
   大字换成实时秒数。

READY 段闭环照跑、目标仍是中心 O，所以球不会滚走，配平滑窗也一直在刷新。
`OL 配平` 那行打出来的角度不合格（超出 ±1°）就别按第二次，先去修 `ZERO`。

第一次按下后如果配平一直不收敛，`配平兜底`(`ARM MAX`，默认 4s)到点会带着现值
进 READY，不会卡死在 `ARMING`。

两个开关组合出三种用法：

| `免回正起跑` | `二次确认` | 行为 |
|---|---|---|
| 0 | 1 | **默认**：按 `TASK3` → 配平 → 出 `START` → 再按一次发车 |
| 0 | 0 | 老行为：按 `TASK3` → 配平 → 配平好了自动发车 |
| 1 | – | 免回正：球由人摆正，按 `TASK3` 立刻发车（`二次确认` 失效） |

跑的过程中屏幕上那个青色大数字就是实时秒数，完成后定格；旁边白字
`+5:0.12 −5:0.28` 是两端实测误差。任何一项超出题目要求（5s / 1cm）
会同时把 `OUT OF SPEC` 标红。

**配平角是在哪一段量的**：走位段是纯开环播表，机械零偏会变成一个常值偏置加速度
一路积成 ½·a_off·T²，只能靠"抄一个闭环托着球停在中心时的平衡角"来抵消。
默认档由 `ARMING`/`READY` 两段负责量它。`免回正起跑`＝1 时这两段都没有了，
就只能改在 `HOLD` 段量（目标同样是中心 O，平衡角同样等于 −机械零偏），
现场变成"先按 `HOLD` 等两秒以上，再按 `TASK3`"。滑窗要 32 帧，20fps 下就是 1.6 秒；
没量够不会拒跑，但日志会打 `OL 配平: 滑窗只有 n/32 帧，本趟不补配平角`。
按 `ZERO` 会清空滑窗（水平基准变了，旧配平角就是错的）。

离线 216 工况（slew 执行器，双段标定 3 趟，误差取球的真值，`+5 / −5` 最坏）：

| 机械零偏 | 配平后自动发车 | **二次确认（默认）** | 免回正、先 HOLD 2s | 免回正、没按过 HOLD |
|---|---|---|---|---|
| 0° | 0.44 / 0.97 cm | **0.45 / 0.89 cm** | 0.45 / 0.80 cm | 0.44 / 1.02 cm |
| +2° | 0.66 / 1.09 | 0.75 / 1.26 | 0.71 / 1.79 | **7.50** / 0.84 |
| −2° | 3.43 / 2.53 | 3.43 / **6.33** | 3.42 / 4.49 | 0.76 / 1.59 |

**零点做准了，几种跑法没有区别**；零点不准的时候数字才开始乱跳。−2° 那一档
本来就已经是 3.43cm 的废成绩（开环对负零偏的固有短板，见 `task3_config.py` §4.4），
二次确认让它散得更开而已。第二次按键的**快慢也不是可调项**：按键延时扫
0/200/500/1000/2000/5000ms，−5 最坏是 6.33/2.36/5.95/5.32/5.73/3.07cm，
非单调——这是在极限环周期上随机取相位，不是"按快了有陷阱"。

所以真正该保证的还是 `ZERO` 做准（目标：日志 `OL 配平` 打出来的角度在 ±1° 以内），
而不是纠结第二次按键什么时候按。

误差是这样量的：`+5` 处取**全程最高点**（命令折返后球还会靠惯性再滑一段，
那个最高点才是评分看到的折返位置）；`−5` 处取"返程最低点"和"稳定段内最大偏差"
中较大的一个（只看其中一个会漏掉另一种失分方式）。

### 不改文件的临时试参

```bash
TASK3_OVERRIDE="kv_near=13,v_max_cms=14" python main.py
```

环境变量压过存档，只认已存在的键，打错字会报出来。
`CTRL_TELEM=1` 每帧打印一行 CSV；`v_ctrl_cms` 是当前模式控制器真正使用的快速球速，
其余内部量也自动取当前正在驱动的 HOLD 或 TASK3 控制器。

### 默认增益的离线验收

`task3_ctrl.py` 不含硬件调用，可以直接在 PC 上接一个球-杆模型跑
（`_sim_task3.py`，临时文件，用法见 `TASK3_现场操作.md` 第 6 节）。

> **早先这里有一张"162 工况、0 失败、最长 4.40s"的表，已经作废。**
> 那份数据的仿真把球速当成理想量（真值加低通），而实际的 `v_cms` 来自
> `AdaptiveAlphaBetaFilter`，速度是位置残差积出来的、滞后约 0.3 秒。
> 换成忠实的观测器模型之后，当时那组默认增益是发散的。
> 现在的模型还照抄了 `main.py` 丢帧那一帧不发电机命令的行为、以及
> `drive_mode=0` 的半帧执行滞后。

216 工况（机械零偏 0/±2°、帧率 20/25/30、连杆比 2.5/3/4、滚动系数 5/7 与 0.55、
观测器 β 相对标称 ×0.5/×2、位置噪声 0/0.8mm，滚阻 1.5 cm/s²），误差取**球的真值**，
执行器取真实的半帧滞后模型：

| 机械零偏 | 纯闭环 最坏 / 最长 | 双段（标定3趟）最坏 / 最长 |
|---|---|---|
| 0° | 1.73 cm / 5.18 s | **0.97 cm / 5.15 s** |
| +2° | 1.28 cm / 5.45 s | 1.09 cm / 5.45 s |
| −2° | 1.32 cm / 5.28 s | 3.43 cm / 4.65 s |

两条要点：

- **双段控制的收益是有条件的**——机械零点准的时候它更准也更快；零偏到 2° 时
  开环那一半会明显变差，因为反对称只能保证"命令角产生的加速度"积分为零，
  机械零偏多出来的常值偏置加速度一路积成 ½·a_off·T²。程序会自动补一部分
  （ARM 段抄闭环的平衡角），但只能减轻不能消除。详见 `task3_config.py` 4.4 节。
- **双段省下的时间没有早先估计的那么多。** 之前记的"实感工况纯闭环 12.85 s、
  双段 3.90 s"是在旧增益下测的；换成 ωn=3 这一族之后，同一工况
  （摩擦 2.5、噪声 0.8mm、20fps、整帧执行滞后）纯闭环是 4.10 s、双段 3.85 s。
  真正被修好的是闭环本身。双段现在剩下的优势是峰值电机角小得多
  （9.0° vs 17.0°）和 DONE 后漂移小（0.19 vs 0.98 cm）。

**这些都是模型结论，不是台架结论。** 摩擦、连杆比、相机延迟都是估的，
台架数据优先于这里任何一个数字。
