# 惯性前馈现场操作

## 1. 作用范围

惯性前馈只作用于 `HOLD` 中心保持。`TASK3` 的 `0 -> +5 cm -> -5 cm`
开环播表、状态机和末端守位控制器没有改动。

最终命令为：

```text
视觉反馈角速度 + 惯性前馈角速度 -> 原行程限幅 -> 积分为电机角度
```

前馈不是用加速度持续积分角度。它先计算一个有限的附加目标倾角，再让实际前馈
倾角受时间常数、角速度和最大角度限制地跟随该目标，因此恒定输入不会把摆杆一直
推向行程端点。

## 2. 接线

- 底盘 `PA8/UART1_TX` -> MaixCAM2 `PA31/UART1_RX`。
- 底盘 GND -> MaixCAM2 GND，必须共地。
- 参数为 `115200, 8N1`，只接收，不回传。
- 必须是 MCU TTL 电平，不能接 RS-232 电平。
- 电机仍使用 `B0/B1 -> /dev/ttyS2`，不要改动。

先在 MaixCAM2 单独运行 `uart_pin_probe.py`。它只读取 `PA31` 的管脚能力，不改
pinmap、不启动电机。主程序固定把 MaixPy pinmap 名称 `A31` 复用为 `UART1_RX`；
不再自动选择其它候选脚。

启动日志示例：

```text
inertia UART: chassis PA8/UART1_TX -> Maix PA31:UART1_RX (/dev/ttyS1)
feed-forward: enabled=0 rx_pin=PA31 port=/dev/ttyS1
```

若没有候选、串口不存在或打开失败，日志会打印 `visual-only fallback`，原视觉闭环
照常运行。

## 3. 协议门控与自动回退

只有同时满足以下条件才施加前馈：

1. 屏幕参数 `FF ON = 1`；
2. 当前模式为 `HOLD`，且本帧识别到球；
3. 协议状态为 `1`（运行）或 `2`（软停）；
4. flags bit2 为 1，即底盘正在执行任务 4/5/6；
5. 序号有更新，最后一个新帧不超过 `FF TIMEOUT`；
6. 帧头、版本、长度和 CRC16-Modbus 全部正确。

任一条件失效时，前馈目标归零并按 `FF RELEASE` 平滑撤销，视觉反馈继续工作。
重复序号不会刷新超时计时。状态 3 且 IMU 有效时，程序自动学习当前所选 IMU 轴的
静态偏置；在第一次学到偏置前，IMU 项为零，PWM 和编码器项仍可使用。

## 4. 第一次启用顺序

默认 `FF ON = 0`，不要直接全项启用。先确认串口与方向：

1. 保持 `FF ON = 0` 启动，查看日志中 RX 管脚；确认接线和共地。
2. 用 `CTRL_TELEM=1` 运行，确认 CSV 的 `ff_ok` 持续增加、`ff_crc` 基本为 0、
   `ff_drop` 不持续快速增加。
3. 先把 `FF K ENC`、`FF K IMU` 调为 0，只保留 `FF K PWM = 0.0010`。
4. 将 `FF MAX DEG` 临时设为 1.0，再打开 `FF ON`，低速推车验证补偿方向。
5. 若底盘开始向前加速时球偏得更严重，把 `FF K PWM` 改成负值；方向正确后再逐步
   增大绝对值。
6. 再加入 `FF K ENC`，最后选 `FF IMU AX=0/1/2`、必要时切换
   `FF IMU INV`，确认状态 3 已完成静态偏置学习后再增加 `FF K IMU`。
7. 最后逐步恢复 `FF MAX DEG`，不建议初次超过默认 4 度。

一次只调一项。验收时在相同底盘任务、相同起始球位下对比 `FF ON=0/1` 的最大位置
误差、回中时间和过冲；任何持续 `FF DATA TIMEOUT`、CRC 增长或方向错误都先关闭
`FF ON`，不要用更大的增益掩盖通信或轴向问题。

## 5. 参数含义

| 屏幕参数 | 含义 | 默认值 |
|---|---|---:|
| `FF ON` | 前馈总开关 | 0 |
| `FF K PWM` | 前进 PWM 变化率到电机附加角度 | 0.0010 |
| `FF K ENC` | 编码器纵向加速度到电机附加角度 | 0.0010 |
| `FF K IMU` | 去静态偏置后的 IMU 加速度到电机附加角度 | 0.0050 |
| `FF IMU AX` | IMU 前向轴，0=X、1=Y、2=Z | 0 |
| `FF IMU INV` | 只翻转 IMU 轴方向 | 0 |
| `FF MAX DEG` | 前馈附加倾角绝对限幅 | 4.0 deg |
| `FF ATTACK` | 有效数据下的跟随时间 | 100 ms |
| `FF RELEASE` | 失效/停车时的撤销时间 | 350 ms |
| `FF TIMEOUT` | 新序号超时阈值 | 100 ms |
| `FF W MAX` | 前馈角速度绝对限幅 | 30 deg/s |

```text

```

```powershell
powershell -ExecutionPolicy Bypass -File .\_snapshots\restore_before_inertia_feedforward.ps1
```

脚本只用快照覆盖当时已有的文件，不删除日志、测试或其它后来新增文件；恢复后的
旧 `main.py` 和旧 `app.yaml` 不会引用前馈模块。
